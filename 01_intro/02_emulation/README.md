# 02 · 用模拟器调通流程，再明确换模型

本项目设计一条从简单势函数到真实电子结构软件的学习路线：哪些步骤可以先用便宜模型调通，哪些结论必须等到目标模型上才能检查。

## 背景：为什么需要这一步

原子模拟中，很多算法只向外询问两件事：当前构型的能量是多少，每个原子受到什么力。它们可以把能量来源看成一个接口，而不必知道内部是解析函数、经验势，还是一次电子自洽计算。

这使我们能先用 Morse 势研究一根键，用二维势研究路径，再把同样的优化或路径工具连接到 GPAW。这里的“模拟器”是便于检查程序的替代模型：它的已知答案、低成本和可控失败有教学价值。它并不自动代表真实材料。

三种差异需要区分：程序是否实现了写下的公式，数值设置是否足以解好这组方程，以及方程本身是否适合实验体系。两套代码在同一模型上相符，主要提供第一类证据；用更密网格得到稳定结果提供第二类证据；第三类需要物理判断或额外参考。

## 开始前需要理解的概念

- **能量/力接口**：输入是同一套坐标与边界条件，输出包括标明单位的能量及力数组。
- **实现错误**：例如把力当成梯度、交换原子索引；在简单模型上就能发现。
- **数值误差**：例如差分步长、SCF 阈值或 k 点不足；必须针对正在求解的方程检查。
- **模型误差**：例如经验势不能描述目标成键或电荷变化；通过所有代码测试仍可能存在。

## 本次任务：从什么得到什么

## 先用一个小例子走通思路

假设自写 Verlet 与 ASE 在同一个 LJ 势上产生相同轨迹，这支持积分器和单位接口的一致性。若随后把势换成 EMT，轨迹变了，这首先意味着运动方程的力变了，而不是 Verlet 突然失效。

类似地，EMT 与 PBE 在一个结构上恰好给出接近的吸附能，不表示它们在其他坐标、位点或过渡态上也相同。必须保持比较层次清楚，才能知道下一次差异应从哪里排查。

本项目要求**手写推理、量纲检查和可否定的判断**。引用前面计算项目的成熟软件结果；不把讨论题包装成返回 true/false 的脚本。必要算术可以使用 NumPy，电子结构、采样与动力学仍由对应项目的软件完成。

```math
\delta E_{obs}=\delta E_{implementation}+\delta E_{numerical}+\delta E_{model}
```

这里只是误差来源的记账框架，不假定三项统计独立，也不意味着可直接加绝对值当置信区间。
